# soil-openapi

OpenAPI 3.1 and TypeScript, generated from the canonical WIT.

```sh
cargo run -p soil-openapi -- --package soil:records --out crates/soil-web-bridge/generated
```

Writes `openapi.json` and `client.ts`. `--stdout` prints both instead.

## Why this exists

A browser is a second host, and a host needs a description of what it serves that
cannot drift from the first one. The canonical contracts already live in [`wit/`](../wit)
and are asserted by `cargo test -p soil-abi`; this crate reads the same
[`CONTRACTS`](../soil-abi/src/lib.rs) table, so a package rename or a dropped
function breaks the generator the same way it breaks the ABI test.

Nothing here reads the Rust implementations. If `WireEntry` and the WIT disagree,
that is a bug the generator exposes rather than one it repeats.

## The mapping

| WIT | wire | TypeScript |
|---|---|---|
| `record` | object, `additionalProperties: false`, every field required | `interface` |
| `updated-at-ms` | `updatedAtMs` (keys are camelCase) | same |
| `enum` / variant case | the WIT name, kebab-case — a *value*, not an identifier | `"not-found"` |
| `variant` | `oneOf` of `{case: payload}` | union |
| `option<T>` | `anyOf [T, null]` | `T \| null` |
| `result<T,E>` | `{ok} \| {err}`, never a half-written union | `{ok: T} \| {err: E}` |
| `list<u8>` | base64 string, `format: byte` | `string` |
| `list<T>` | array | `T[]` |
| `resource` | opaque id string | `string` |
| `u64` | `format: uint64` — a number JS cannot always hold | `number`, with the caveat in the description |

Errors are values: a `soil:*` failure is `{"result":{"err":{"code":…,"message":…}}}`, and
`code` is the package's own WIT `error` enum, referenced rather than inlined.

## What is derived, and from what

- `openapi.json` describes the *transport* the bridge actually answers:
  `POST /v1/call` with a per-function `oneOf` of request bodies, the WebSocket
  upgrade, `/healthz`, the bearer scheme, and every WIT type as a component.
- `client.ts` describes the *calls*: `Operations` correlates each request with its
  response, which OpenAPI cannot express. That is why the client is generated
  from the WIT rather than from the document.

Both are checked in under `crates/soil-web-bridge/generated/` and regenerated by a
test that fails on any difference — the artifacts are reviewable and cannot go
stale without the suite saying so.

## Checks

```sh
cargo test -p soil-openapi          # drift + every $ref resolves + shape assertions
npx tsc --noEmit --strict --target es2022 --lib es2022,dom crates/soil-web-bridge/generated/client.ts
npx @redocly/cli lint crates/soil-web-bridge/generated/openapi.json
```

Redocly reports zero errors. Its remaining warnings are
`no-illogical-composition-keywords` on the request union: the branches are in fact
exclusive (each pins a different nested `call.function` const), but the rule only
compares top-level properties.
